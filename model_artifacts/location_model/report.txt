--- Structural findings (step-4 investigation) ---

1. dist_victim_km distribution within groups:
   - 50.2% of groups: true ATM IS the nearest candidate (rank 1 by distance).
     The baseline captures these correctly, so it's hard to beat.
   - 75th-pct true ATM rank: 18/21. Top 25% of hard cases have true ATM
     ranked near-last by distance. The monotonic constraint correctly prevents
     these from being scored high — but can't overcome the distance penalty
     using case-level features alone (which are constant within a group).
   - True ATM median distance from victim: 333 km (mean 574 km).
     Nearest candidate median: 64 km. The task is genuinely hard for a
     distance-only ranking signal.

2. same_bank_as_terminal = 0 for ALL rows — root cause confirmed:
   - ATM CSV uses full official names: "STATE BANK OF INDIA" (94%) / "INDIAN BANK" (6%)
   - Snapshots use abbreviations: SBI, BOB, HDFC, ICICI, Axis, PNB, Kotak, Union
   - These never match → feature is always 0.

3. Bank name fix attempted and REVERTED (2026-09-04):
   - Added ATM_BANK_NORM mapping (STATE BANK OF INDIA → SBI) in both
     build_location_candidates.py and demo_app.py.
   - Result: same_bank_as_terminal gained non-zero importance (3.36), but
     stolen_amount exploded to gain=100 (was 0), and val accuracy DROPPED
     from 47.59% to 42.07%.
   - Root cause: with same_bank_as_terminal now splitting SBI-terminal groups,
     the model used stolen_amount (a group-level constant, useless for within-
     group ranking) as a secondary splitter, chasing spurious case-level patterns.
     Both train and val dropped — the bank signal was misleading, not helpful.
   - Fix reverted. known-good state (val=47.59%) fully restored.
   - Even if the mapping worked cleanly: 94% of ATMs are SBI → near-zero
     discrimination power within SBI-terminal groups. The data incompatibility
     (real 2-bank ATM CSV vs synthetic 8-bank case data) is not fixable without
     richer ATM data.

4. Why early stopping fires at round 1:
   - Case-level features (terminal_readiness, n_hops, stolen_amount, urban,
     is_final_snapshot) are CONSTANT within each ranking group → cannot help
     rank one candidate over another.
   - same_bank_as_terminal = 0 always → zero signal.
   - Only candidate-specific signal is dist_victim_km and dist_terminal_km, both
     monotonically constrained. Round 1 encodes this monotone distance relationship
     optimally; additional rounds can't find valid improving splits under the
     constraints. Model converges immediately.

--- What would actually help (if this is revisited) ---

  location, ATM hours, or local crime pattern features.
- Use richer bank data (real multi-bank ATM CSV) so same_bank_as_terminal fires
  with actual signal.
- Or accept the current performance as the structural ceiling given available data.
